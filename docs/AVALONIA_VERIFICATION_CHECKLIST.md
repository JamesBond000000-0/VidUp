# Avalonia GUI Preview 検証・引き継ぎチェックリスト

作成日: 2026-10-24

## 1. この手順書の目的と現在地

開発者以外の確認担当者が、背景を知らなくても同じ手順で確認し、結果を開発者へ返せるようにするための文書です。
対象は `VidUp.Desktop` の**初期GUI試作**です。完成版の移行受入試験ではありません。

**作成時点で、ビルド・NUnitテスト・実GUI確認はすべて未実行です。** 作業環境に.NET SDKがなく、公式SDK配布元とNuGetに接続できなかったためです。静的なXML/リンク/差分確認だけを行っています。以下のチェック欄は合格済みを意味しません。

最初の到達目標は次の3点です。

1. 必要な環境で、他人が依存復元・ビルド・自動テストを再現できる。
2. WindowsでGUIが起動し、現時点で実装した基本操作が動く。
3. 試作を操作しても、元動画や既存VidUpデータを変更しない。

## 2. 担当・優先度・結果の付け方

### 誰が何を行うか

| 担当 | 実施内容 |
|---|---|
| 環境/CI担当 | E01〜E04。SDK・依存復元・ビルド・自動テスト・成果物を確認 |
| Windows操作確認担当 | G01〜G10、S01〜S02。日本語入力・DPI・ファイル操作を実機で確認 |
| 性能/開発担当 | P01〜P02。大量データと購読/メモリの問題を測定・切り分け |
| レビュー担当 | 結果・証跡・残課題を確認し、次段階へ進めるか判断 |

1人が兼任して構いません。担当者名と確認対象リビジョンを必ず記録してください。

### 判定ルール

- **PASS**: 手順を実行し、期待結果を満たした。証跡を残す。
- **FAIL**: 実行できたが期待結果と異なる。再現手順と問題番号を残す。
- **BLOCKED**: SDK未導入、ネットワーク制限等で実施できない。理由と解除に必要な対応を残す。
- **N/A**: 対象外。理由とレビュー担当者の合意を残す。必須項目を都合よく除外しない。
- **未実施**: まだ実行していない。空欄も未実施として扱う。

チェック欄は**PASSになったときだけ**チェックします。BLOCKEDを「問題なし」と扱わないでください。

優先度は、**必須**（初期試作の確認完了に必要）、**追加**（次段階に向けた測定）、**環境依存**（利用する経路のみ必須）の3種類です。

### テストファイルを用意する（Windows PowerShell）

以下は一意な一時フォルダーに小さなダミーファイルを作ります。**実動画ではありません**が、現在のPoCは内容を解析しないため、追加UIの確認に使えます。将来実アップロードを実装した版では、この手順のまま送信しないでください。

```powershell
$testDir = Join-Path $env:TEMP ('VidUp-Preview-Check-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $testDir | Out-Null
@('日本語の動画.MP4', 'second.mkv', 'notes.txt') | ForEach-Object {
    [IO.File]::WriteAllText((Join-Path $testDir $_), 'preview-only dummy data')
}
New-Item -ItemType Directory -Path (Join-Path $testDir 'folder.mp4') | Out-Null
$before = Get-ChildItem -LiteralPath $testDir -File | Get-FileHash -Algorithm SHA256
$before | Export-Csv -LiteralPath (Join-Path $testDir 'hash-before.csv') -NoTypeInformation
$testDir
```

`$testDir` のパスを記録してください。別のPowerShellを開いた場合は変数が消えるので、記録したパスを再設定します。

## 4. 環境・ビルド・自動テスト

### E01 SDKと依存復元【必須】

**意図:** 「コードの不具合」と「環境が足りない」を区別するため。

1. セットアップ文書に沿って.NET 10 **SDK**を導入する。
2. リポジトリ直下で `dotnet --version`、`dotnet --info` を実行する。
3. `dotnet restore VidUp.Desktop.Tests/VidUp.Desktop.Tests.csproj` を実行する。

**期待結果:** `global.json` に適合する.NET 10 SDKが選択され、restoreの終了コードが0。Runtimeのみの導入では合格にしない。

**証跡:** SDK情報、restore全文、終了コード。ネットワーク失敗はBLOCKEDとし、接続できないホストとエラーを記録する。公式でないパッケージ配布元へ勝手に切り替えない。

- [ ] E01 PASS

### E02 ReleaseビルドとViewModelテスト【必須】

**意図:** C#だけでなくXAML/型付きBindingのビルドと、検索・追加・重複除外等のロジックの回帰を検出するため。

1. Windows: `./scripts/check-desktop.ps1` を実行する。
2. Linux: `bash scripts/check-desktop.sh` を実行する。
3. スクリプトを実行できない場合は、セットアップ文書のrestore/build/testコマンドを個別に実行する。

**期待結果:** 全コマンドの終了コードが0、テスト失敗・実行中断なし。テスト数、成功/失敗/スキップ数を記録する。警告は隠さず記録し、新規警告は開発者へ確認する。

**証跡:** ビルド・テストの全文。必要に応じて `dotnet test VidUp.Desktop.Tests/VidUp.Desktop.Tests.csproj -c Release --logger "trx;LogFileName=desktop-preview.trx" --results-directory artifacts/test-results` でTRXを残す。自動テスト通過だけではGUI確認完了としない。

- [ ] E02 PASS

### E03 GitHub Actionsと配布物【環境依存: CI/成果物を利用する場合】

**意図:** 開発者のPC固有の環境に依存せず、配布される実ファイルも起動できることを確認するため。

2. Windows/Linux両ジョブのbuild/test結果を確認する。
3. Windows成果物 `VidUp-Desktop-Preview-win-x64` を取得し、専用フォルダーへ展開する。
4. 展開された `VidUp.Desktop.exe` をWindows x64上で起動する。

**期待結果:** 両ジョブ成功。Windows publish/upload成功。成果物から起動してG01と同じ画面になる。実行されていないジョブを成功扱いしない。

**証跡:** Actions実行URL、SHA、ジョブ結果、起動画面。成果物保持期限が切れた場合は再実行を依頼する。

### E04 Dev Container / Linux仮想画面【環境依存: この経路を利用する場合】

**意図:** 文書だけでなく、環境定義を第三者が再現できるか確認するため。

## 5. Windows GUI操作（実機）

起動: `dotnet run --project VidUp.Desktop/VidUp.Desktop.csproj -c Release --no-build`。
各項目は、必要に応じてアプリを再起動して初期状態へ戻してください。

### G01 起動と試作であることの表示【必須】

**意図:** 利用者が本番版・実際のアップロード状態と取り違えないようにするため。

**手順:** 起動直後のヘッダー、注意文、3件のキュー、詳細、開始ボタンを確認する。

**期待結果:** 試作版・サンプルと判断できる表示がある。3件は「サンプル」、開始は無効。起動時例外・空白画面がない。

**証跡:** 全画面スクリーンショット、起動ログ。

- [ ] G01 PASS

### G02 選択と詳細の整合【必須】

**意図:** 編集・送信先の取り違えにつながる、行選択と詳細の不一致を早期に検出するため。

**手順:** サンプルを上から順に選択し、タイトル・ファイル・アカウント・テンプレート・公開日時・状態を行と比較する。

**期待結果:** 選択のたびに対応した詳細へ切り替わり、前の行の値が残らない。現在は読取専用である。

**証跡:** 少なくとも2件の選択画面。差異があれば項目名と実際の値。

- [ ] G02 PASS

### G03 検索・0件・選択解除【必須】

**意図:** フィルターがキューを削除したり、非表示行の詳細を誤って表示したりしないことを確認するため。

**手順:** `日常チャンネル` で検索 → 存在しない文字列で検索 → 入力をすべて消す。

**期待結果:** 1件 → 0件と空状態案内 → 元の3件に戻る。0件時は前の詳細値が残らない。表示件数も整合する。

**証跡:** 検索語・各段階の件数と画面。

- [ ] G03 PASS

### G04 ファイル選択・重複・キャンセル【必須】

**意図:** 追加の基本導線と、意図しない二重登録・キャンセル時の状態変更を確認するため。

**手順:** プレビューをクリア → 「動画を追加」で `日本語の動画.MP4` と `second.mkv` を複数選択 → 同じ2件を再選択 → ファイル選択を開いてキャンセル。

**期待結果:** 最初に2件追加される。再選択では0件追加・2件スキップとなり、キューは2件のまま。キャンセルでも件数は不変。詳細のファイルパスが正しい。

**証跡:** 通知文と件数、ファイル選択方法。複数選択できなければFAIL。

- [ ] G04 PASS

### G05 ドロップと対象外ファイル【必須】

**意図:** 別の追加経路にも同じ検証・重複除外が働き、フォルダーを動画と誤認しないことを確認するため。

**手順:** プレビューをクリア → エクスプローラーからテストフォルダー内の動画2件、`notes.txt`、`folder.mp4` フォルダーを一緒にキューへドロップ → 動画2件をもう一度ドロップ。

**期待結果:** 動画2件だけ追加される。テキスト・フォルダーは追加されない。再ドロップで重複しない。フォルダーはUI側で除外されるためスキップ通知に数えられない場合があるが、登録されないことを確認する。

**補足:** 存在しないファイルは通常のエクスプローラーではドロップできない。欠損パスの除外はE02の自動テストで確認する。GUI上で無理に再現する必要はない。

**証跡:** ドロップ対象一覧、追加後の件数・通知文。

## 6. データ安全性

### S01 元ファイルの不変【必須】

**意図:** 「追加・クリア」は元の動画を削除/書換えしないという最重要の保証を確認するため。

**手順:** G04/G05を行い、プレビューをクリアして終了。その後、準備時のPowerShellで次を実行する。

```powershell
$baseline = Import-Csv -LiteralPath (Join-Path $testDir 'hash-before.csv')
$baseline | ForEach-Object {
    if (-not (Test-Path -LiteralPath $_.Path -PathType Leaf)) {
        'MISSING: ' + $_.Path
    } elseif ((Get-FileHash -LiteralPath $_.Path -Algorithm SHA256).Hash -ne $_.Hash) {
        'CHANGED: ' + $_.Path
    } else {
        'UNCHANGED: ' + $_.Path
    }
}
```

**期待結果:** 基準の全ファイルが `UNCHANGED`。1件でもMISSING/CHANGEDならFAILとし、その後の操作を止めて開発者へ連絡する。

**証跡:** 比較結果。元ファイルの内容を公開する必要はない。

- [ ] S01 PASS

### S02 既存プロファイルへ触れない【必須】

**意図:** 本番データと試作の責務分離が保たれているかを確認するため。

**手順:** 実データを持ち込まず、使い捨てWindowsユーザー等で確認することを推奨。既存データがある場合はWPF版を停止し、対象フォルダーをバックアップする。起動前後で既存JSON/画像のファイル一覧・更新日時・ハッシュを比較する。保存先は通常Documents配下のVidUpだが、リダイレクトやsuffix/subFolderがあるため実環境の場所を確認する。

**期待結果:** 既存JSON/画像が新規作成・更新・削除されない。ログイン要求・アップロード動作・電源操作が起きない。プロファイルがない環境では「新規プロファイルが作られない」ことを記録する。

**証跡:** 比較結果のみ。トークン、client secret、JSONの生データは添付しない。利用者データ保護が難しい場合はBLOCKEDとして専用環境を用意する。

- [ ] S02 PASS

## 7. 性能・長時間操作

### P01 1,000件の追加と表示【追加】

**意図:** 仮想化リストの採用だけで快適になったと判断せず、同期ファイル検証や全件再構築による停止を測るため。

**準備:** 専用フォルダーに小さいダミー1,000件を生成する。

```powershell
$bulkDir = Join-Path $testDir 'bulk'
New-Item -ItemType Directory -Path $bulkDir | Out-Null
1..1000 | ForEach-Object {
    [IO.File]::WriteAllText((Join-Path $bulkDir ('video-{0:D4}.mp4' -f $_)), 'preview-only')
}
```

**手順:** Release起動 → プレビューをクリア → 1,000件を選択して追加 → 最下行までスクロール → `video-0999` 検索 → 検索解除。追加完了時間、検索反応時間、追加前後のメモリを記録する。

**期待結果:** 1,000件・重複なし、検索1件、解除で1,000件へ戻る。クラッシュ・継続的な操作不能がない。検索反応200ms以内は設計上の暫定目標であり、達成済みではない。手動で測れない精度は「測定不能」とし、体感を数値にしない。

**証跡:** 端末仕様、測定方法、時間、タスクマネージャー等で見たメモリ指標名と値。追加が重い場合は既知の同期処理制限として課題化する。

- [ ] P01 PASS

### P02 画面往復・メモリ傾向【追加】

**意図:** 画面切替や選択の反復による状態増殖・購読リークの兆候を探すため。

**手順:** 1,000件表示後、ナビ切替・復帰・検索/解除を20回実行。開始直後/途中/操作後しばらく待った時点の同じメモリ指標を記録する。

**期待結果:** 行が増殖せず、操作性が継続的に悪化しない。メモリが増え続ける場合は調査対象とする。単発の増加だけでリークと断定しない。

**証跡:** 各時点の値・経過時間・操作回数。

- [ ] P02 PASS

## 10. 完了判断と引き継ぎ

- E01/E02、G01〜G10、S01/S02がPASSで、証跡とレビューがあることを初期試作の確認完了条件とする。
- 利用した環境経路のE03/E04もPASSが必要。利用していない経路は理由付きN/Aとし、未検証であることを残す。
- 必須項目のFAIL/BLOCKEDが残る間は「確認完了」としない。部分的な設計・開発を進める場合も未完了のまま明記する。
- P01/P02未実施や問題は次段階へ引き継ぎ、大量データ対応済みとは表記しない。
- データ変更・削除、送信など想定外の危険動作があれば直ちに停止し、証跡を保全して開発者へ連絡する。
- 完了後も「初期試作の確認」であり、移行完了・正式リリース可の判断ではない。

証跡を共有する前に、ユーザー名、ローカルパス、アカウント名、動画タイトル等を必要に応じてマスクしてください。認証トークン・client secret・Authorizationヘッダーを添付してはいけません。
